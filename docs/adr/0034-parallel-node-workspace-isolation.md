# Parallel repository nodes require isolated workspaces

Software R&D Department nodes that execute concurrently against the same repository must use separate Worktrees or isolated Sandbox workspaces, with independent branches, sessions, checkpoints, and artifact outputs. Join and Review nodes consume commits, patches, and registered Artifact Versions rather than a shared mutable directory, and only dedicated Runtime-owned import/integration/release operations may update their respective host refs.

A formal Work Package additionally requires Git-ref write isolation: the Agent executes against an independent Git database and cannot write the host/shared Git common directory; a Runtime-owned importer validates and advances only the allocated source branch. A bind-mount that exposes shared `.git` state and direct no-sandbox host execution do not satisfy this requirement, even when serialized. They remain supported only for explicitly snapshotted compatibility nodes that cannot produce Work Packages, Code Review inputs, Integration Generations, or Delivery Candidates, unless a future wrapper proves equivalent ref isolation through capability tests. The selected provider and per-execution `head`, `branch`, or `merge-to-head` strategy are captured in the Run Configuration Snapshot and cannot change silently; the formal Work Package profile narrows this to `branch` plus `gitRefWriteIsolation` and `runtimeImportOnly`.
