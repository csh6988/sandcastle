# Independent Code Review creates exact, isolated Integration authority

Formal Code Review reuses the generic Review Runtime for Topics, findings, bounded discussion, revisions, fresh rechecks, and immutable Gate Results, while a dedicated deep module freezes the Work Package-specific manifest and composes Reviewer Workspace, Defect/rework, and Integration-authority policy. The Runtime freezes two distinct eligible non-producer identities: one supplies the initial independent finding and the other supplies the fresh recheck from a new Session attached to the declared `code-review@1` Node. The initial Reviewer receives an independent read-only Workspace whose allowlisted root contains the detached source tree plus the frozen manifest and canonical Git diff; the built-in local adapter uses an independent clone and blocks when that isolation cannot be established. Provider isolation is proven through intent/reconcile evidence, and failure blocks the Review Node and Run through the Pipeline Runtime rather than downgrading to shared execution.

Only a current independent code-kind `PASS` bound to the exact active Work Package Version, Runtime-imported source commit, canonical Diff bytes and hash, self-check, and independence evidence creates immutable Integration authority. Query-time eligibility revalidates those exact inputs and rejects any package-level open Defect. `CONDITIONAL_PASS` and `FAIL` instead create durable Defects and fresh Work Package execution resources while retaining all prior evidence; a fresh `PASS` over the exact rework Version closes the tracked rework obligation without rewriting its prior Gate or evidence. Downstream Integration therefore never infers approval from mutable status, a historical Gate, or Developer self-check.
