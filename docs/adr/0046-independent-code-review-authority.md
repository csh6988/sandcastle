# Independent Code Review creates exact, isolated Integration authority

Formal Code Review reuses the generic Review Runtime for Topics, findings, bounded discussion, revisions, fresh rechecks, and immutable Gate Results, while a dedicated deep module freezes the Work Package-specific manifest and composes Reviewer execution, Defect/rework, and Integration-authority policy. The Runtime freezes two distinct eligible non-producer identities: one supplies the initial independent finding and the other supplies the fresh recheck from a second new Session attached to the declared `code-review@1` Node. The Reviewer input bundle contains only an exact detached Git object set, the frozen manifest, and the canonical Git diff; that bundle is an allowlist boundary, not proof of runtime isolation. Formal readiness comes from the durable execution receipt of the actual Reviewer Sandbox. The production adapter accepts only a fresh Docker execution with the bundle mounted read-only at `/review`, a launcher repository with no producer context, private container HOME/cache/Session state, and disabled Session capture. Bind-mount, no-sandbox, missing receipts, unknown operations, or invalid output evidence block the Review Node and Run rather than downgrading to shared execution.

Only a current independent code-kind `PASS` bound to the exact active Work Package Version, Runtime-imported source commit, canonical Diff bytes and hash, self-check, fresh recheck Session, and execution-bound isolation evidence creates immutable Integration authority. Query-time eligibility revalidates those exact inputs and rejects any package-level open Defect. `CONDITIONAL_PASS` and `FAIL` instead create durable Defects and fresh Work Package execution resources while retaining all prior evidence; a fresh `PASS` over the exact rework Version closes the tracked rework obligation without rewriting its prior Gate or evidence. The shared `code-review@1` Node is an aggregate barrier: it remains running until every current active Work Package Version has eligible authority, then records the sorted Version IDs, Authority IDs, code-kind Gate Result IDs, and their `coverageHash` as the internal authority consumed by Integration. Downstream Integration therefore never infers approval from mutable status, a historical Gate, a single package's PASS, or Developer self-check.
