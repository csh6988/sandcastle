# Reviewed Memory materializes only after independent Review and enters execution through a child Snapshot

T25 keeps raw transcripts and legacy Memory records outside the governed execution context: an AI member may propose a redacted Memory Candidate only from exact Project-scoped Artifact Versions and Runtime Event ranges under a Runtime-registered redaction-policy version/hash, the generic Review Runtime must produce an independent exact `PASS`, and a verified human decision alone materializes one immutable Memory Entry. Neither the producer nor an AI member targeted by a Candidate may vote on it. Entries are never loaded through a mutable latest-value lookup; a verified human explicitly selects exact Entry IDs, versions, and hashes, Pipeline Runtime appends a child Snapshot revision while preserving every earlier Snapshot, and Runtime Memory resolves those exact refs into scoped Entry content only when a later formal execution starts. This concentrates provenance, review, decision, receipt replay, redaction enforcement, and scope isolation behind the Runtime Memory interface, prevents self-promotion and cross-Project leakage, and keeps Pipeline Runtime as the sole Snapshot writer.
