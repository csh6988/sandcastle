# Software delivery uses a supervised multi-role production pipeline

The built-in Software R&D Department uses a supervised, role-separated production pipeline instead of one omnipotent Agent or a user-operated chain of ad hoc chats. The user works directly with the Product manager until explicitly confirming the Product Baseline; the Delivery coordinator then orchestrates bounded product and technical Review topics, versioned Project and Application Specs, repository readiness checks, Work Package fan-out, isolated Worktree execution, independent code review, integration, Test runs, Security review, Operability review, and Delivery candidate assembly. Runs advance automatically between the requirement-confirmation and human-release gates, but every Agent session remains observable, replayable, pausable, and subject to governed intervention through Company Runtime evidence and immutable Snapshot revisions. Reviewers and testers use independent Sessions and cannot approve their own production work; parallel developers never share a writable Worktree; conflicts and failures become traceable defects that return to the responsible Work Package. Passing Agent gates creates an immutable Delivery candidate rather than deploying production, and execution statistics may only generate human-reviewed Improvement proposals instead of automatically mutating Harnesses, Specs, templates, or Skill Flows. This design preserves industrial throughput without sacrificing separation of duties, runtime authority, local safety, evidence, or human control.
