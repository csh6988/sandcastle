# Idempotent post-Run Release operations

T22 defines Release as a post-Run destination effect that consumes only `DeliveryRuntime.acceptedAuthority(candidateId)`. The accepted authority is destination-free and remains the sole upstream input; a second verified local-session human authorization creates each Release operation. One accepted authority may support multiple operation IDs, but an operation ID is immutable: replay with the same canonical request returns its existing intent or receipt, while changed input fails with `RELEASE_OPERATION_ID_REUSE`.

Every intent freezes its canonical request hash, accepted authority snapshot, ordered Items, destination, expected state, and idempotency key before any external effect. SQLite records that intent transactionally, but the merge/export Adapter executes outside the transaction. A later finalize/reconcile unit records a safe receipt, failure, destination conflict, or unknown observation. This gives restart recovery evidence without blind resend and leaves the foundation free of a real Adapter or shared command wiring.

`merge` must cover every Repository commit in the authority and is fast-forward-only. A checked-out target, a missing/invalid target, divergence, or a source not covered by authority fails closed. A target already containing the source produces a succeeded `no-op` receipt; Release never creates a merge commit. `export` permits a non-empty authority Artifact subset only, to a pre-existing local filesystem root identified by its canonical path. Each Artifact has one exact relative path and may use `create-only` or `replace-if-exact-digest`; only verified managed-file or repository-object content is eligible, while external references are rejected.

Items execute in frozen serial order. Failures and destination conflicts are retained while later Items continue; an `unknown` Item stops remaining work and makes the aggregate `blocked`. States are `pending`, `running`, `reconciling`, `succeeded`, `failed`, `destination-conflict`, and `unknown`; successful Items carry `applied` or `no-op` receipts. Drift is a destination conflict on the old Item and needs a new operation. Reconciliation is a verified-human evidence command, not an authorization to treat an unverified destination as successful.

Release does not alter Pipeline, accepted authority creation, sandbox providers, branch strategy, sessions, completion signals, ACP, root APIs, or Runtime IPC. Query Views reconstruct authority, immutable request, aggregate/counts, Items, safe receipts/evidence, next actions, and timestamps. Runtime Events are invalidation-only; schema v51 adds persistence tables and event registry v19 preserves all v18 contracts.
