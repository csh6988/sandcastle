# Pipeline Runtime durable execution leases

Pipeline Runtime stores time-bounded execution and reconciliation leases on each Node Attempt and owns claim, renewal, completion, failure, release, and expiry recovery in SQLite transactions. The same fenced execution-lease protocol also applies to standalone Product Discovery and Consultation Interaction Turns, whose lease target is the Turn rather than a Node Attempt; run-collaboration Turns share the bound Node Attempt lease.

Expiry, an unproven pause, or an unproven cancellation moves a running target to an explicit reconciliation-required state rather than a rewritable terminal state or silent queue. Pause keeps the Run paused while the active Attempt/Node become reconciling/blocked; Resume returns it to blocked until reconciliation settles that Attempt. Cancellation marks and releases the old execution Lease, but Adapter cancellation responses remain advisory until the Runtime accepts a terminal Fact or later reconciliation evidence. A unique recovery owner claims a reconciliation lease for the stable execution operation key. Runtime binds each Adapter fact sink to the active lease epoch/fence, and reconciliation or reattachment receives a newly bound sink; Adapter return values may only reference a terminal fact already accepted through that sink. A `not-started` result is valid only when that reconciliation sink has accepted a terminal fact with Provider receipt/evidence proving the operation key never began. The same Attempt or Turn may continue only when the Adapter proves the external operation is still running and supports reattachment. A new Attempt/Turn is allowed only after an accepted provider terminal fact or verifiable strong fence proves the old operation cannot continue; unknown or unobservable execution remains reconciling and blocked, and a human decision alone cannot convert uncertainty into termination. Protocol, Supervisor, IPC, and Renderer layers only observe the resulting state.

For a Node Attempt, the bound sink is the only accepted execution write path. It canonicalizes and hashes each unfenced Adapter fact, stamps the stable operation key, target, lease kind, epoch, and fence token, and persists accepted, duplicate, stale, or conflict evidence in one SQLite unit of work. Fact identity is `(operationKey, factId)` and ordering is `(operationKey, executionEpoch, ordinal)`; identical identity and hash replays the original receipt, while identity, ordinal, and terminal compare-and-set conflicts remain diagnostic evidence and cannot overwrite state. Accepted terminal facts atomically drive Attempt/Node/Run state, Permission, Artifact lineage, Runtime Audit, and Event Outbox effects. A released or expired fence can still be recorded as stale evidence, but it cannot mutate the current Attempt. Scripted and Production Execution Adapters therefore submit only `AdapterExecutionFact` bodies and may return only a receipt for an accepted terminal fact; they do not have a second completion channel or direct state-write authority.

Retry, Recovery, and Fork remain separate continuation operations. Retry appends a new Attempt under the same Snapshot, Recovery appends a new Snapshot revision and Recovery Attempt, and a boundary-changing Fork creates a child Run while atomically superseding its parent. Recovery and Fork persist an immutable, hash-checked Continuation Plan in the same transaction; the Plan and every Plan Item reject update and deletion, and every Node/Gate is assigned exactly one `rerun`, `reuse-evidence`, `skip`, or `blocked` disposition so restart never reconstructs reuse decisions from mutable current state.
