# Formal local execution uses a private Git database and Runtime-owned CAS import

T13 defines `software-rnd-local-isolated-git` as the built-in formal local Execution Profile. It resolves to the Docker Sandbox provider with the `branch` strategy and freezes a capability snapshot that proves `gitRefWriteIsolation` and `runtimeImportOnly`; the default no-sandbox profile and the `test-isolated` test provider are not formal profiles. Provisioning clones the allocated source commit into an Agent-writable execution tree with an independent Git common directory, removes host remotes, disables hooks and recursive submodules, and persists the private Git identity before execution. The Company Runtime records allocation and source-import intents, Audit records, Runtime Events, and Command receipts in one SQLite Unit of Work, while Git provisioning/import/cleanup remains an external idempotent side effect recovered at startup. Import accepts only the exact private branch tip descended linearly from the allocated base, verifies Git object integrity and path policy, rejects symlinks/submodules and protected metadata, transfers objects through a temporary bundle, and advances only the allocated host source ref with expected-tip `update-ref` CAS. A crash after the Git CAS but before SQLite finalization is reconciled as the same duplicate import with a durable object-set receipt; tip drift remains a failed import and is never force-updated. This preserves the Agent's ability to use normal Git inside Docker without exposing the host Repository's writable Git database or allowing the Sandbox to choose integration refs.
