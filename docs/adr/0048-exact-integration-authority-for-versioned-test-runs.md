# Versioned Test Runs consume exact Integration authority

Test Runs consume one exact immutable `PASS` Integration Generation, including its manifest hash, `passAuthorityHash`, reviewed coverage lineage, aggregate Review evidence, and per-Repository integrated commits, then freeze that authority together with Test Case revisions, build, Snapshot, Execution Profile, fixture, environment, evidence policy, and the deterministic Test-scope risk policy, factors, computed tier, evidence, and hashes. Runtime validates that calculation and exposes it unchanged in downstream PASS authority so T18 never reconstructs risk from mutable state. Runtime must not reconstruct a Test input from a mutable branch tip, latest Generation, current Work Package state, Renderer projection, or Agent statement; changed code or Integration inputs require fresh Code Review and Integration authority, while a fixture or Test Case revision change may create a fresh Test Run against the same unchanged Generation.

Pipeline Runtime remains the sole writer of Department Run, Node Run, and Node Attempt state. Its Test-specific SQL and state mapping live in a private Pipeline collaborator behind the existing narrow transition seam, while the Test module owns Test Run manifests, durable execution intent/fact/receipt reconciliation, paired UI/Runtime assertions, evidence, defects, and downstream PASS authority. This keeps Test-specific complexity local without introducing a second Pipeline state machine; unknown or non-terminal external effects block for reconciliation instead of being blindly resent or converted into a fabricated failure.

A failed, blocked, or cancelled Test Run may create only a fresh rework Test Run. The Runtime routes persisted responsibility to the exact Work Package, producer/consumer Contract, UI/Runtime contract owner, or explicit aggregate/unknown triage candidates rather than trusting caller attribution. Changed code or Integration lineage requires fresh T15 Code Review and T16 PASS Integration authority; a Test Case or fixture-only revision may reuse the exact unchanged PASS Generation, but receives fresh Test Run and request identities and never rewrites historical evidence.

The scoped Electron fixture proves this contract through the built renderer, preload bridge, Runtime child process, Company Database, Pipeline, Artifact Registry, audit records, and Runtime Events. Runtime setup creates the prerequisite Product, Technical, Work Package, Code Review, Integration, and Artifact authority through formal Commands and registered handlers before reconciliation or listening; the driver never opens the Company Database or registers Artifact Versions. A real BrowserWindow click starts an accepted execution which becomes terminal only through reconciliation; assertion evidence must carry an acknowledged token for the complete authoritative Query View hash, Artifact locators come from the Registry's safe inspection view, cleanup proves the frozen temporary Repository and Worktree are absent, reload restores from the Query View, and the one-time launch claim cannot be reused. Scripted adapters remain confined to allowlisted test-build execution ports and cannot be selected by a production renderer, ACP command, or ordinary environment variable.
