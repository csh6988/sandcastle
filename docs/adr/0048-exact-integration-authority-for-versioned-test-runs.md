# Versioned Test Runs consume exact Integration authority

Test Runs consume one exact immutable `PASS` Integration Generation, including its manifest hash, `passAuthorityHash`, reviewed coverage lineage, aggregate Review evidence, and per-Repository integrated commits, then freeze that authority together with Test Case revisions, build, Snapshot, Execution Profile, fixture, environment, evidence policy, and the deterministic Test-scope risk policy, factors, computed tier, evidence, and hashes. A Build Artifact is eligible only when its producer lineage names that same PASS Generation and exact integrated commits. The Runtime derives a fixed risk rubric from the Technical Baseline promoted by the frozen Snapshot, rejects caller-selected rules or incomplete factors, and exposes the validated risk unchanged in downstream PASS authority so T18 never reconstructs it from mutable state. Runtime must not reconstruct a Test input from a mutable branch tip, latest Generation, current Work Package state, Renderer projection, or Agent statement; changed code or Integration inputs require fresh Code Review and Integration authority, while a fixture or Test Case revision change may create a fresh Test Run against the same unchanged Generation.

Pipeline Runtime remains the sole writer of Department Run, Node Run, and Node Attempt state. Its Test-specific SQL and state mapping live in a private Pipeline collaborator behind the existing narrow transition seam, while the Test module owns Test Run manifests, durable execution intent/fact/receipt reconciliation, paired UI/Runtime assertions, evidence, defects, and downstream PASS authority. Reconciliation persists its intent, Test state transition, Runtime event, audit record, and receipt through the worker unit of work. Explicit failed assertions terminalize the Test Run as `failed`; missing or unknown assertions terminalize it as `blocked`; both create deterministic evidence-backed Defects and obligations. Unknown or non-terminal external effects likewise block for reconciliation instead of being blindly resent or converted into a fabricated failure. Runtime-generated assertion identities use the injected deterministic ID source so equal seeds and clocks reproduce equal records.

A failed, blocked, or cancelled Test Run may create only a fresh rework Test Run through `test.rework.create`; direct Test Run creation cannot bypass an open related Defect. The Runtime persists the prior manifest, Defect, responsibility route, and whether Integration authority is reused or replaced as hash-bound rework lineage. It routes persisted responsibility to the exact Work Package, producer/consumer Contract, UI/Runtime contract owner, or explicit aggregate/unknown triage candidates rather than trusting caller attribution. Defects and obligations remain append-only, accept at most one immutable resolution, and close only when that resolution cites paired passing assertions and evidence from the exact fresh PASS Test Run. Changed code or Integration lineage requires fresh T15 Code Review and T16 PASS Integration authority; a Test Case or fixture-only revision may reuse the exact unchanged PASS Generation, but receives fresh Test Run and request identities and never rewrites historical evidence.

The scoped Electron fixture proves this contract through the built renderer, preload bridge, Runtime child process, Company Database, Pipeline, Artifact Registry, audit records, and Runtime Events. Runtime setup creates the prerequisite Product, Technical, Work Package, Code Review, Integration, and Artifact authority through formal Commands and registered handlers before reconciliation or listening; the driver never opens the Company Database or registers Artifact Versions. A real BrowserWindow click sends a consultation prompt through preload, consumes the scripted adapter facts, and proves the resulting Interaction Turn, output, audit, and cursor-recoverable Runtime Events before assertion evidence is accepted. Assertion evidence must carry an acknowledged token for the complete authoritative Query View hash. Fixture files are opened from a component-by-component symlink-free path with no-follow semantics, inspected and hashed from the same descriptor, and the verified bytes are passed directly into Artifact registration. Registry-inspected evidence locators and cleanup prove the frozen temporary Repository and Worktree are absent, reload restores from the Query View, and the one-time launch claim cannot be reused. Scripted adapters remain confined to allowlisted test-build execution ports and cannot be selected by a production renderer, ACP command, or ordinary environment variable.
