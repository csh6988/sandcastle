# Versioned Test Runs consume exact Integration authority

Test Runs consume one exact immutable `PASS` Integration Generation, including its manifest hash, `passAuthorityHash`, reviewed coverage lineage, aggregate Review evidence, and per-Repository integrated commits, then freeze that authority together with Test Case revisions, build, Snapshot, Execution Profile, fixture, environment, and evidence policy. Runtime must not reconstruct a Test input from a mutable branch tip, latest Generation, current Work Package state, Renderer projection, or Agent statement; changed code or Integration inputs require fresh Code Review and Integration authority, while a fixture or Test Case revision change may create a fresh Test Run against the same unchanged Generation.

Pipeline Runtime remains the sole writer of Department Run, Node Run, and Node Attempt state. The Test module owns Test Run manifests, durable execution intent/fact/receipt reconciliation, paired UI/Runtime assertions, evidence, defects, and downstream PASS authority, and requests only narrow legal Pipeline transitions. This keeps Test-specific complexity local without introducing a second Pipeline state machine; unknown or non-terminal external effects block for reconciliation instead of being blindly resent or converted into a fabricated failure.
