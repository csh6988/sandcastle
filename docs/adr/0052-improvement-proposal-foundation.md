# Frozen Statistics evidence governs append-only Improvement revisions

T26 uses a pure live `statistics.inspect` Query plus an explicit `statistics.evidence.freeze` Command because current Runtime projections cannot replay an arbitrary historical sequence. The immutable evidence snapshot binds `statistics@1`, the canonical Project-scoped filters, cohort, comparison set, UTC half-open window, Runtime `asOfSequence`, observations, completeness, authority, and hash. An Improvement proposal revision binds exactly one snapshot and one strict governed target: Harness, Project Spec, Application Spec, Runtime-owned template, or governed Skill Flow. Every proposal revision is immutable and receives at most one exact verified-human decision; changing evidence, target identity/head/content, or validation policy requires a new revision and a new decision.

Approval is advisory authority only and creates no target revision. Apply and rollback are separate verified-human application operations with immutable intent, a mutable state projection, and append-only receipts, observations, reconciliation, validation, and rollback evidence. Their target-specific adapters may only append Company Runtime-governed revisions. Project/Application Spec adapters use append-without-current-pointer seams; Harness, Runtime template, and governed Skill Flow use dedicated append-only stores. No operation changes a current Run or Snapshot, publishes or activates configuration, writes repository/template files, invokes an Agent/provider, or performs network/deployment work. Unknown effects are inspected and reconciled without blind resend; rollback appends a restoring revision while retaining the applied revision.

Schema v52 stores these contracts and Runtime Event Registry v20 adds only `statistics.evidence.invalidated`, `improvement.proposal.invalidated`, and `improvement.application.invalidated`. The existing typed Command/Query/View tunnel carries all T26 operations without a new Electron IPC channel; renderer Commands omit actors, and Runtime derives Project-read, worker, or verified-human authority from the authenticated principal.

For governed execution reliability, `statistics@1` uses the existing immutable or terminal Runtime facts without substituting configuration. Concurrency is the maximum overlap of exact execution-Lease intervals clipped to the requested UTC half-open window; reconciliation Leases are excluded. Ordinary Retry and Recovery count Node attempts by their distinct `retry` and `recovery` reasons at attempt creation. Department Run and Node Attempt failure rates retain literal failed and comparable terminal denominators, while cancelled or interrupted work remains outside those failure denominators. Lease interruption uses ended execution Leases and treats an absent or late release at the expiry boundary as interrupted. Human approval wait requires a valid request/decision-or-expiry timestamp pair for every Approval requested in the window. Governed intervention rate is the share of window-member Node attempts with an exactly attributable governed intervention; missing attempt attribution makes the observation incomplete. Department and Pipeline Version filters use their exact Run lineage, while unavailable AI Member, Model, Repository, or Work Package attribution is reported rather than guessed.
